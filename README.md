# CS-320-Software-Test-Automation-QA-

<h2>Reflections on Software Testing, Automation, and Quality Assurance</h2>

This repository presents artifacts from my software testing course, such as the contact service and its JUnit tests from Project One, as well as my summary and reflections report from Project Two. These projects illustrate my comprehension of software requirements, unit testing, validation, and quality assurance.

<h3>How can I ensure that my code, programs, or software systems are both functional and secure?</h3>

I ensure that my software is functional and secure by developing tests that verify both expected behaviors and potential failure scenarios. Throughout this course, I utilized JUnit to test valid and invalid inputs, duplicate IDs, and service operations. I learned that successful code execution does not guarantee correct functionality. Testing must also assess how software responds to unexpected inputs and errors. To further enhance security and reliability, I plan to incorporate input validation, additional security testing, and regular regression testing as the software evolves.

<h3>How do I interpret user needs and integrate them into a software application?</h3>

I interpret user needs by identifying requirements and translating them into specific features and expected behaviors. For instance, the contact service required unique IDs, field-length restrictions, and the ability to add, update, and delete contacts. These requirements guided my class design and informed the focus of my JUnit tests. I consider communication and clarification essential, as assumptions about user expectations may result in errors or unnecessary development.

<h3>What is my approach to software design?</h3>

My approach to software design begins with understanding the requirements and determining how components should interact. I break complex problems into smaller, manageable parts, ensuring each component has a defined responsibility. In this project, separating the contact object from the contact service enabled independent testing of data validation and service operations. I also emphasize the importance of maintaining readable, organized code that can be modified and tested as requirements evolve. In future projects, I intend to incorporate testing earlier in the development process to identify issues before they escalate.
